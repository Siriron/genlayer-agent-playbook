- **Shipped-contract exposure to the `status_code` bug (audited Sep 2026, `genvm-lint` plus source read of all eight repos):** seven of eight use `getattr(response, "status_code", None)`; only ReturnRecord (which uses `render`) does not. Impact differs by how each contract consumes the fetch:
  - **ProofPulse (rejected) — broken outright.** `_evaluate_sla` reads `int(getattr(r, "status_code", 0) or 0)`, which is always 0. Simulated with the SDK's real `Response` fields: a healthy HTTP 200, a 503, and a 404 all resolve to `SLA_BREACHED` with `http_code` 0. `SLA_MET` and `PARTIAL_BREACH` are unreachable in practice, so the four-outcome ladder its README describes does not exist. Fix is `.status`; do not resubmit without it.
  - **Recourse and Copyleft (accepted) — the documented `[fetch failed: HTTP n]` marker never appears for HTTP errors.** A 404/403/500 page reaches the model as if it were the deliverable / LICENSE text. Only DNS and connection failures (the `.invalid` live test) produce the marker. Confirmed by executing the real Recourse contract in direct mode (Sep 2026): with a 404 deliverable URL the model's prompt contained the page body and not the failure marker, and with the model mocked to read the body as a missing page the engagement went `non_compliant` → `cure_pending`; with an unreachable host the marker appeared and the engagement went `unverifiable_pending_refine`. What a real model would say to a 404 page is not proven, only that it is never told the fetch failed.
  - **SentinelSLA, RecallGuard, MilestoneVault (accepted) — mostly absorbed by structural checks.** SentinelSLA's `register_sla` requires `full_name` in the repo record and `resolve_compliance` requires a matching `source_code_location`, so a 404 body still voids; only the void reason is mislabeled (`ADVISORY_REPO_MISMATCH`, never `FETCH_FAILED_GHSA`, for HTTP errors). RecallGuard requires a list of dicts. MilestoneVault's prompt tells the model a 404 body means the criterion is unmet.
  - **FilingWatch (rejected):** same pattern in `_fetch_json`; consequence depends on the SEC response body. Not analyzed further.
  - Accepted, live contracts are not redeployed for this alone; fix it in every new build and before any resubmission.
- **Floats:** GenVM ADR-007 — float operations are software-emulated (deterministic) in deterministic mode, and the linter does not flag `float()`. Section 3's ban stays as this project's stricter rule.
