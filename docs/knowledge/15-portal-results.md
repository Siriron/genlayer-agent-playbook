**Rejected, with the staff's reason (verbatim in substance)**
- **ProofPulse (Sep 14):** the resolution checks the endpoint only at resolution time, so it cannot show whether the SLA was met during the claimed incident window. A resubmission needs authenticated, independently timestamped evidence tied to that immutable window, with protection against self-claims and replayed incidents. (Same family as Chronomark's deadline-precommitment rejection. Separately, the contract has the `status_code` bug in section 14.)
- **FilingWatch (Sep 20):** the recurring workflow advances each deadline without advancing its reporting period, so later checkpoints can reuse the original filing; and the comparative rule refers to fields removed from the canonical result instead of reliably comparing the consequential standing. It uses `gl.eq_principle.prompt_comparative`. This is the failure section 2 warns about: an equivalence string that does not cover the decision-bearing fields. Use a hand-written validator that re-derives and compares every consequential field.
- **ReturnRecord (Sep 19):** the non-voided renter lifecycle is not demonstrated by admissible repository evidence. The included tests are static and pure-model checks that explicitly do not execute GenVM consensus, and the deployment address and transaction log cannot be used in a repository-only review.

**New review standard visible in these decisions**
- **Review is repository-only.** Deployment addresses, transaction logs, and explorer links are not accepted as proof. Behavior has to be demonstrated by tests inside the repo.
- **Tests must execute the contract under GenVM consensus**, not model it in plain Python. That points at direct-mode tests (`genlayer-test` with `run_validator`); they do run against the pinned runner (see section 14) and section 16 has the template and checklist. Earlier feedback on Recourse ("add a repository-level lifecycle test that proves the terminal state and both transfers") and MilestoneVault ("test payout, disagreement, fetch failure, replay, and recovery cases") asks for the same thing.
- **Every funds path needs a bounded exit.** MilestoneVault: a bounded expiry or refund path so failed evidence retrieval cannot lock funds forever. Copyleft's staff note (accepted anyway): it does not fetch the disputed files it claims to judge, can leave stakes permanently locked, and needs immutable repository binding, fail-closed handling of missing evidence, and filing and cure timeout finalization with transfer-path tests. RecallGuard: the app must show the balance and call `withdraw()`.
- **The app must complete every flow.** SentinelSLA: challenge and finalization in the app, and return the created check ID instead of inferring it from a global counter. RecallGuard: connect-and-act so the first write does not use stale wallet state. This matches the DomainClaim "global counter minus one" rejection.
- **Bind everything to canonical, registered identifiers.** SentinelSLA (accepted after fixes): canonical owner/name binding, a repo-backed ownership proof file, rejection of duplicate and invalid filings, and fix references matched to the registered repo before finalization.
- **Copyleft's 200 pts came with the staff caveats above**; it was not a clean pass. Treat the known gaps (timeout finalization, permanently locked stakes) as real defects if that contract is ever revisited.
