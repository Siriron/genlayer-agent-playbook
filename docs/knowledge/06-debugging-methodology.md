## 6. GenVM debugging research methodology — how to actually verify a fix instead of guessing

This is the process that found and confirmed all seven bugs in section 4 (six from Copyleft's debugging history, one from Recourse's). Apply it to any future GenVM error rather than pattern-matching from general blockchain/Python intuition — GenVM's API surface is not the same as ethers.js/web3.py/Solidity, and plausible-sounding method names (like `.send()`) frequently don't exist.

1. Never guess an SDK method name or behavior. If it isn't in this document, verify it via live web search before writing code that depends on it.
2. Get the actual stderr/traceback, always. GenLayer Studio Explorer's Transaction Details to Stderr field gives the exact file/line/exception type — this is ground truth, and a vague description of "it errored" is not a substitute for it. Ask for the real traceback before theorizing.
3. Cross-reference multiple independent official sources before trusting any single pattern. GenLayer's own docs contain at least one confirmed internal inconsistency (see Bug 2's note on the `custom_consensus_example` snippet). A single doc page or example can be stale or illustrative-only. Trust the pattern confirmed by the most independent sources, especially the canonical getting-started example (WizardOfCoin), over an isolated one-off.
4. Priority order of doc pages to check for any nondet/consensus/storage question (fetch the first one for almost any GenVM question — it's the single largest, most complete page):
   - docs.genlayer.com/full-documentation.txt
   - docs.genlayer.com/developers/intelligent-contracts/features/error-handling
   - docs.genlayer.com/developers/intelligent-contracts/features/non-determinism
   - docs.genlayer.com/developers/intelligent-contracts/features/web-access
   - docs.genlayer.com/developers/intelligent-contracts/features/calling-llms
   - docs.genlayer.com/developers/intelligent-contracts/storage
   - docs.genlayer.com/developers/intelligent-contracts/security-and-best-practices/prompt-injection
   - The SDK API reference at sdk.genlayer.com is often JS-rendered — a direct fetch may only return the page shell; targeted web-search queries against it tend to surface real content in search-result snippets even when a direct fetch doesn't.
5. Real deployed contracts on the actual explorer are extremely high-value ground truth. Browse explorer-studio.genlayer.com's Contracts tab or search by function name pattern — a contract implementing something similar in production reveals defensive patterns (e.g. the "Faults" error-reconciliation pattern found during this debugging) that official docs may not cover at all.
6. Independent real-developer testimony (blog posts, build logs from people who've actually shipped on GenLayer) is a third, distinct kind of source from official docs and deployed contracts — it surfaces hard-won lessons ("you cannot access self inside a nondet block") that may never be explicitly stated in official documentation but are empirically true.
7. Don't declare victory after one plausible-sounding fix. Test the actual failure signal directly (empty stderr, no warning text, correct settlement math via balance arithmetic) rather than "the transaction didn't throw that specific error anymore." Fixing one bug frequently exposes the next bug further down the same code path — this happened on every single one of Copyleft's six bugs.
8. Run the complete mandatory audit in section 4 before every deploy — not just the parts that feel relevant to the current error (ten confirmed bugs feed this list, plus three checklist lines that aren't numbered "Bugs" since they're code-review and tooling checks rather than GenVM runtime behaviors — verdict-enum reachability, the `status_code` grep, and the `genvm-lint check` run; keep this list, section 4's bug count, and this note in sync going forward, since a stale count here is exactly the kind of discoverability gap this project has already been bitten by once):
   - Grep for `.send(` on any `get_contract_at()`/`ContractAt()` result to must be `.emit_transfer(value=...)`.
   - Grep for `self.` anywhere inside a nested function passed to `run_nondet_unsafe`, or inside any instance method that IS such a function to must be zero matches outside comments.
   - Check every class-body attribute with a type annotation — is it genuinely meant to be mutable, per-instance storage? If not, move it to module level.
   - Grep for `json.loads(` on anything derived from `run_nondet_unsafe`'s return value or a `leaders_res` parameter to must be zero matches (these are already-decoded types).
   - Check every `self.some_storage_field` access for whether it could execute inside a nondet block to must use `gl.storage.copy_to_memory()` first, extracted in the plain deterministic body.
   - Grep for `float(` anywhere reachable from nondet code, even transiently to must be zero matches.
   - Confirm `run_nondet_unsafe(leader_fn, validator_fn)` is called positionally, never with `leader_fn=`/`validator_fn=` keywords.
   - **Grep for `DynArray[...]()` or `gl.storage.inmem_allocate(DynArray[...])` on any nested `@allow_storage` dataclass field — both raise live (Bug 7), and the confirmed-safe alternative (a top-level contract field, or a delimiter-joined `str` for per-record arrays) needs to be used instead.**
   - **For any contract with an enumerated verdict/outcome type: list every value the enum can take, and next to each, name the actual `leader_fn` code branch that could produce it (confirmed rejection pattern, RetractionWatch, Aug 2026 — see section 2's verdict-enum-reachability note and section 11's full entry). A value accepted by `validator_fn`'s membership check but unreachable by any `leader_fn` branch must be deleted or made reachable before submitting — a docstring disclosing the gap does not satisfy this.**
   - **Grep for `status_code` anywhere in contract code — must be zero matches outside comments (SDK `Response` has `.status`; `status_code` is always `None` and disables the HTTP-error check).**
   - **Run `genvm-lint check <contract.py>` — must pass with no errors (E010: a `gl.nondet.*` helper unreachable from a leader/validator fails).**

**Note on Bugs 11 and 12 (section 4) — deliberately NOT included in the ten-item list above.** Both are real, worth-testing candidate patterns adapted from an external contract, but neither has cleared a live GenLayer Studio deploy as of this writing (see their full write-ups in section 4 for exactly what's confirmed vs. asserted). Adding either to this mandatory audit before a live test would misrepresent an open question as a settled rule. Claude can offer to write the isolated test for either, once, when relevant — but the safe, already-confirmed default (delimiter-joined `str` for Bug 11, `_now_epoch_seconds()` for Bug 12) stays in place regardless of whether the person chooses to test. If and when either is confirmed live, promote it into this list and update the count.
